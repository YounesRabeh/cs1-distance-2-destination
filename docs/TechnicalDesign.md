# Technical design

## Overview

Distance 2 Destination reads the route that Cities: Skylines has already created for the selected entity. It never starts pathfinding and never changes simulation data.

The main components are:

- `PathDistanceCalculator` validates the selected vehicle or walking citizen and captures its current route state.
- `PathHelpers` traverses the remaining path and measures its geometry.
- `VehicleInfoPanelPatch` and `CitizenInfoPanelPatch` refresh the display.
- `DistanceLabel` owns the added UI row and restores the original panel layout during cleanup.
- `ModSettings` stores visibility and unit preferences.
- `Patcher` applies and removes owner-scoped Harmony patches.

## Supported entities

Vehicles must be created, spawned road vehicles. A trailer or consist member is resolved to the first vehicle that owns the route.

Citizens must have a live walking `CitizenInstance`, must be on a path, and must not be entering or riding a vehicle. Embedded citizen panels inside private-vehicle windows are ignored.

The citizen field is shown only while the vanilla activity starts with **Going**. The vehicle field is removed for a stationary parking vehicle.

## Existing-path traversal

Vehicles and pedestrian instances expose an existing `m_path` and encoded path-position index. A path consists of chained `PathUnit` structures, each containing up to 12 network positions.

Traversal is defensive:

- Only ready, allocated path units are accepted.
- Every unit, segment, lane, and buffer index is validated before use.
- Cycles are rejected.
- Traversal is capped at 4,096 path units.
- The root and current entity state are checked again after reading to detect release, reuse, or rerouting.

Invalid or changing state returns an unavailable result instead of a partial distance.

## Distance model

Path positions identify a segment, lane, and byte offset from 0 through 255. The calculator resolves each position to its vanilla `NetLane` geometry.

Partial lane lengths are measured by sampling the lane's Bézier curve. Samples are separated by no more than 16 offset units.

When a route changes lanes, the path does not retain the exact connector curve generated by each vehicle or citizen AI. Distance 2 Destination therefore creates a tangent-aligned cubic connector between the vanilla-derived endpoints and approximates its arc length with 16 samples.

During a transition, the entity's current world position is matched to the nearest connector sample so only the remaining part is counted. The result is more representative than a single straight line but remains an approximation of the AI-specific movement curve.

The accumulated value uses game world units as metres. Unit selection affects formatting only:

- Metric uses metres and kilometres.
- Imperial converts metres to feet and miles.

## Display and refresh

Harmony postfixes run after vanilla updates `VehicleWorldInfoPanel` or `CitizenWorldInfoPanel`. Each patch verifies that its own top-level panel and selected entity match before attaching UI.

The distance row is a sibling below the vanilla Status row. The containing information window grows by the row height plus bottom padding. Removing the row restores the original sizes.

The selected route is recalculated at most once every 0.75 seconds while a supported panel is visible. No city-wide scan or background worker is used.

## Dependencies and lifecycle

Distance 2 Destination ships `CitiesHarmony.API.dll` but not the Harmony implementation. `Mod.OnEnabled` asks the API to ensure Harmony is installed. Patches are applied only when Harmony is available and are removed using the owner ID `com.distancetodestination.cs1`.

## Known limitations

- AI-specific intersection connectors are approximated because their generated curves are not stored in `PathUnit`.
- The game may release a route shortly before changing its visible activity, producing a temporary dash near arrival.
- The implementation is verified against Cities: Skylines 1.21.1-f9; another assembly layout requires compatibility testing.
